# M3 native verification fixtures

`interface_shc_math_test.cpp` is the host-only assertion test for directed and inverse pair signs, periodic seams, nonperiodic cuts, the reference MIC branch, compact selection/bounds, sparse candidate completeness and slot/coefficient equivalence, bilateral correlations, grid-resolution rejection, and analytic versus numeric trapezoid integration. `interface_shc_stats_test.cpp` also checks separate spectra/fluxes for two blocks against their cumulative spectrum mean. The unified C++14 host test entry point is `../interface_native/`; its build/test commands are in that directory's README. The separate CUDA CMake target remains below.

`interface_sampling_time_test.cpp` calls the production fixed-step/time helpers for one million 1 fs steps, large run starts at 2000 ps and 10000 ps, a rejected 0.5 fs change, and full blocks with sample intervals 1 and 3. `interface_shc_stats_test.cpp` calls the production block-range and Welford helpers; it checks the 100/10 two-block mean of 55, first-block `nan` error, second-block error of 45, and cumulative/current ranges. Both are built and run by CTest through the unified C++14 `../interface_native/` project.

The SHC action now stores sampled plane flux in a reusable GPU buffer sized for one block and copies sampled rows directly into the preallocated host cache only at block boundaries. The GPU atom history remains bounded by the selected plane atoms and `Nc`; the host cache grows with all sampled flux rows and complete-block correlations. The action prints both allocations before the run. It writes flux, correlation, cumulative spectrum, and per-block spectrum data during `post_run`, so a process interruption before then can lose the buffered results. A tail block keeps flux rows but contributes no spectrum. The per-block spectrum is `m3_shc_blocks.out` in the runtime fixture and has its own 11-column schema. The empty-plane fixture verifier checks zero plane flux, correlation, cumulative spectrum, and per-block spectrum output when no atoms are selected.

`nep_plane_flux_consistency.cu` directly constructs the repository's `NEP` class using `tests_pytest/fixtures/models/nep_C.txt`. It sets `N1=0, N2=N`, builds a distorted diamond cell with 21.402 A periodic x/y and nonperiodic z, arms the production sparse `NEPPlaneFluxView`, and compares site energies, forces, and virials with the view disabled. It finite-differences the actual NEP site-energy partition for atoms on both sides of an internal plane at two displacement sizes, then checks the partition energy-rate identity against the captured plane flux. It also builds two production sparse plane maps on periodic x (the box seam and an interior cut), checks the distinct seam/internal coefficient signs on both sides by finite differences, compares periodic view-on/off energy/force/virial, and checks `dE_slab/dt = Q_left-Q_right`. Its equal-duration NVE Verlet paths at 0.2 and 0.1 fs bound endpoint and maximum running energy-ledger residuals by `1e-3 eV + 10%` of signed integrated boundary exchange and require improvement at the finer step unless both residuals are below the 1e-3 eV floating floor. This is the real NEP consistency test; it does not copy the NEP derivative formula into the test.

The standalone CMake target links the existing NEP, neighbor, potential, DFTD3, box, and required utility translation units without linking the GPUMD main. Its default CUDA architecture is sm_60 because the production NEP path uses double-precision `atomicAdd`; override it for a modern GPU when building locally. With CUDA Toolkit and an available GPU, run it using:

```
cmake -S . -B build -DCMAKE_CUDA_ARCHITECTURES=89
cmake --build build --config Release
ctest --test-dir build -C Release --output-on-failure
```

The build command creates the CUDA consistency executable. The M0-M3 host-only tests run from the C++14 suite in `../interface_native/`; the architecture override is optional, and the standalone CUDA target uses the sm_60 default when omitted. For a single-configuration generator, `--config Release` may be omitted or selected with `-DCMAKE_BUILD_TYPE=Release` at configure time.

The existing `run.in` fixture exercises the registered Action on a deterministically initialized, slightly distorted 6x6x6 diamond-carbon input for eight steps, producing two complete four-sample blocks. `verify_fixture.cpp` checks nonzero finite flux/correlation, finite two-block errors, the version-3 SHC schema, cumulative and current-block time ranges/sample counts, both sampling metadata headers against `time_step * TIME_UNIT_CONVERSION * sample_interval / 1000`, and consistency of the exported-grid trapezoid with the analytic partial-range integral. Run the GPUMD executable from this directory, then compile and run the verifier with a host C++17 compiler.

`tests_regression/interface_native` now defines opt-in CTest runs for the actual profile/SHC Action and NVE integrator, plus geometry split, legacy fallback, explicit-empty-SHC, and long heat_lan paths. The NVE fixture is homogeneous diamond and deliberately configures no physical interfaces but two bulk sampling planes; it proves SHC coordinates do not create M1 `interface_crossing` labels. The geometry split fixture separately checks that a nonempty physical plane flags only its bin while a sampling plane in another bin controls SHC IDs. A second runtime fixture omits sampling planes and verifies parser fallback for unsorted `interfaces 2 7 3`.

The heat fixture uses a nonperiodic transport axis and transverse PBC, with 10,000 warm-up steps followed by candidate production at reported steps 10001-20000. It checks source/sink counter signs, paired per-block plane/bath residuals, half-window stability, system-energy slopes, same-block flux/C0, and full-Nyquist integration of actual exported spectrum rows. Explicit block-SE budgets reject statistical insufficiency rather than allowing large noise to hide imbalance; neighboring blocks are not asserted independent. Thresholds remain uncalibrated until run. All-carbon runtime fixtures verify software paths, not heterogeneous-material transport.

`empty_plane/run.in` is a separate small orthogonal-box input with its nonperiodic plane in vacuum, outside the selected-atom cutoff. Its verifier checks that the zero-selected-atom path emits finite zeros without launching zero-sized GPU work. `unsupported_ensemble/run.in` is an expected-failure input for the `ti_spring` rejection guard.

These fixtures are software-path checks, not material-property validation. In the current environment no CUDA/C++ compiler or GPUMD executable is available, so none of the C++/CUDA assertions, build target, or runtime inputs have been run.
