# Native interface closure report

## Scope and boundary

This pass changes native C++/CUDA, native fixtures, and documentation only. It does not add Python analysis, Phonopy parsing/projection, wavepacket generation, IFC2 residual calculation, or modal-power analysis. The checkout began at `feature/interface-phonon-dynamics`, HEAD `68fe16317413d20b79fe11ba5773c72a08b8d203`; no commit or branch change was made.

## Round 1: native closure pass

## A. Separate physical interfaces from sampling planes

`InterfaceGeometry` requires `interfaces` and accepts an optional `sampling_planes` key. Each coordinate list is parsed and independently wrapped on a periodic axis, sorted, range-checked, checked for finiteness, and rejected if coordinates duplicate after wrapping. Omitting `sampling_planes` copies the normalized physical interface list, preserving the previous coordinate order and zero-based IDs. An explicit empty list remains valid for geometry/profile outputs; `compute_interface_shc` rejects it before allocating plane buffers.

M1's `interface_crossing` flag is still derived exclusively from physical interfaces. SHC selection, plane counts, compact candidate mappings, coordinates, and output IDs all use `sampling_planes_A`. The JSON metadata is version 2, retains `interfaces_A`, and adds `sampling_planes_A` with the sorted-coordinate plane-ID rule. Each of the four SHC outputs records its geometry source and sampling coordinates.

The C++ host test covers independent lists, fallback ordering, independent PBC normalization, duplicate wrapped coordinates, material-bin crossing separation, and an empty sampling list. Geometry-only and SHC runtime verifiers cover serialized metadata and explicit-empty rejection. The runtime fixtures were authored but not executed.

## B. Independent native SHC physics and runtime checks

The CUDA NEP consistency program continues to call the production `NEP::compute` and `NEPPlaneFluxView` with the repository's single-element `nep_C.txt` NEP4 model. It retains view-on/off energy, force, and virial comparison; ordinary carbon-NEP radial/angular coefficient finite differences; and the single nonperiodic-plane energy-rate check. The model does not enable ZBL, so ZBL derivatives and multi-element AlAs/GaAs interfaces are not covered. The test adds a periodic-x slab bounded by the seam and an internal plane, uses distinct seam/internal coefficient signs for finite differences on both sides, compares same-configuration periodic view-on/off energy/force/virial, and checks the slab identity `dE_slab/dt = Q_seam - Q_inside`. Its equal-duration velocity-Verlet paths at 0.2 fs and 0.1 fs check endpoint and maximum running ledger residuals against `1e-3 eV + 10% * abs(integrated signed boundary exchange)` and require the finer-step residual to improve unless both are below the 1e-3 eV floor. Printed diagnostics include delta E, integrated flux, absolute exchange activity, endpoint/max residual, and tolerance. The test uses the production sparse candidate map and does not duplicate NEP derivative formulas.

Optional GPUMD CTests prepare distorted diamond-carbon models under fixed build-tree runtime paths and reference the repository's existing `nep_C.txt`. The NVE/profile/SHC verifier checks M1 crossing labels, nonzero flux, same-block mean flux and C0, and the trapezoid integral recomputed from exported frequency rows. The fixture uses the full Nyquist bound for 0.5 fs and verifies run-derived `dt_ps`, frequency endpoints/order, and sample/plane/block ordering. Separate `geometry_split` and `geometry_legacy` fixtures exercise the actual parser/action path: the former puts a physical plane in bin 1 and an independent sampling plane in bin 4; the latter omits `sampling_planes` and supplies `interfaces 2 7 3`. The explicit-empty-sampling-plane run must fail at the SHC guard after geometry metadata has been written.

The opt-in `heat_lan` fixture runs 10,000 warm-up steps followed by candidate production at reported steps 10001-20000, then checks two candidate halves. It requires source-positive/sink-negative resolved signals, block-SE budgets for each bath/plane signal, paired source/sink and plane/bath residuals, stable half-window bath/plane powers, and bounded blockwise total-system-energy slopes. Paired residual SE is used so correlated quantities are not treated as independent; adjacent blocks are not assumed independent confidence intervals. The source-defined thresholds are software gates and have not been calibrated by a run.

The CMake project defines host preparation/verifier targets that do not depend on GPUMD. Runtime CTests register only when a nonempty `GPUMD_EXECUTABLE` names an existing file; an invalid nonempty value is a configure error. Fixture cleanup requires a normalized direct child of the configured build directory's `runtime` folder and rejects symlinks/path escapes before removal. The longer heat-lan case additionally requires `GPUMD_RUN_LONG_INTERFACE_TESTS=ON`. Every fixture writes beneath this build runtime tree and does not copy the potential into the source tree.

These all-carbon runs check Action, mapping, and integrator plumbing. They are not a heterogeneous-interface or material-property validation. No AlAs/GaAs potential or structure was available, and no heterointerface result is claimed.

## C. M4-M6 native data contract and performance scope

The local `dump_interface_atoms` output remains a selected-window input substrate for user-written analysis. JSON and groups/dump headers identify M0 positions as `geometry_mapping_only` and state `equilibrium_reference=external_required`. These are wrapped pre-run grouping coordinates, not a guaranteed equilibrium harmonic `R0`. A shifted wavepacket input would therefore make them unsuitable as the equilibrium reference. The local dump has no t=0 frame; downstream mode work must separately retain initial positions, matching IFC2/eigenvectors, masses, global IDs, cell indices, and phase information. No mode import or projection was added.

`model.xyz` velocity input and NVE remain available. Existing FCP order-2 support still reads `r0.in`, `fcs_order2.in`, and `clusters_order2.in`; FCP stores coordinates and force constants as `float`, forms `u=x-r0` without MIC, and subtracts mean force equally across atoms. It has no arbitrary constant `F_ref` input. The documentation gives a small non-crossing displacement/finite-difference check procedure rather than claiming all IFC inputs are valid.

For M6, external analysis must compare the active force with `F_harm=F_ref-Phi*u` on the same instantaneous configuration. It must not subtract separately propagated trajectories frame by frame, and the sampled core needs a halo large enough to supply IFC2-neighbor displacements. Snapshot force is the current per-atom force and includes enabled action contributions; the suggested diagnostic run is controlled pure-NEP NVE. No IFC2 residual or modal-power calculation was added. M7 lifetime/MFP/recovery analysis and M8 mass-scaling mismatch analysis remain unimplemented; native per-atom mass input and propagation already exist.

M3 retains block-boundary D2H and `post_run` output. CPU result caches scale with total sampled flux rows and complete blocks; GPU atom histories scale with selected atom-plane slots times `Nc`. The docs include a short-window memory estimate and warn that an interruption before `post_run` can leave only headers. No streaming/checkpoint mode, hard memory cap, warp reduction rewrite, or unmeasured GPU optimization was added. `run.cu` keeps the original MD-loop time/speed and adds post-run duration plus the combined timed-loop/post-run rate.

## Round 2: directed review response

1. **Periodic seam signs and view invariance:** the finite-difference expectation now contains separate seam/internal-boundary orientation and atom-side signs. The periodic view-on result is compared with a same-state view-off evaluation through the same E/F/virial helper as the nonperiodic case.
2. **NVE energy ledger:** each 0.2/0.1 fs trajectory records endpoint and maximum running `E_slab(t)-E_slab(0)-integral(Q_left-Q_right)` residuals in eV. Each must satisfy `1e-3 eV + 10% * abs(integrated signed boundary exchange)`, nonzero signed exchange is required, and the finer step must reduce the max residual unless both steps sit at the 1e-3 eV floor.
3. **Full-Nyquist runtime spectrum:** 0.5 fs fixtures request the Nyquist endpoint at high precision with 65 grid points. The verifier reads input/output `dt` and frequency metadata, checks full range plus row/block/step/plane order, then integrates the actual written frequency rows and compares with same-block C0 and mean flux. The exported-spectrum integration tolerance is `5e-11` times the absolute trapezoid area to account for 12-significant-digit output rounding when positive and negative spectral areas cancel; the C0-to-mean-flux comparison retains its tighter existing tolerance.
4. **Geometry parser regressions:** `geometry_split` verifies a nonempty physical boundary in bin 1 and a separate sampling plane in bin 4; only bin 1 may carry the profile crossing flag, while all SHC headers report the sampling coordinate. `geometry_legacy` omits the sampling key and starts with `interfaces 2 7 3`; actual geometry, M1, and SHC outputs must use sorted `[3,7]`. The fixtures use all-carbon atoms and validate software labels, not real material interfaces.
5. **Heat-lan acceptance:** the opt-in run now has 10,000 warm-up steps followed by candidate reported steps 10001-20000. It checks two halves, sign and variability for source/sink/bath/both planes, paired source-sink and plane/bath residuals, half-to-half bath/plane stability, and block total-energy slopes. Paired residual SE has a hard budget; excess dispersion reports `statistics_insufficient` and fails. Adjacent blocks are not claimed independent.
6. **Fixture deletion boundary:** the runner requires build root, mode, verifier, and other files; requires `CMakeCache.txt`; resolves the fixed `runtime/interface_<mode>` parent and rejects symlink/path escapes before `REMOVE_RECURSE`. A nonempty invalid `GPUMD_EXECUTABLE` is a configure error.
7. **Verifier include:** `<cstdio>` is explicit in the fixture verifier. Assertions remain active in Release through `#undef NDEBUG` before `<cassert>`.
8. **Reference metadata:** JSON and the first groups/dump headers now say `reference_positions_role=geometry_mapping_only`, `equilibrium_reference=external_required`, and `dump_interface_atoms` has no t=0 frame. Numeric data columns remain unchanged.
9. **Parser consolidation:** `interfaces` and `sampling_planes` share count and coordinate parsing while retaining their distinct diagnostics and seen/fallback behavior.

## Round 3: final verifier correction

- Runtime verifiers now use the production completed-step index (`1..N`) for profile and SHC rows. Expected sample times and block start/end times use those same completed steps; the NVE check explicitly joins profile energies and SHC flux by the shared step key. The heat steady window is reported as steps 10001-20000 after 10,000 warm-up steps.
- The full-Nyquist spectrum verifier also integrates the absolute trapezoid area and allows `5e-11 * absolute_trapezoid` for 12-significant-digit row rounding. It asserts finite, strictly increasing frequency rows. The same-block C0-to-mean-flux comparison keeps its existing tighter tolerance, and the NVE nonzero-exchange assertion remains.
- The model used by the finite-difference executable is the single-element `nep_C.txt` (`nep4 1 C`): it exercises ordinary carbon-NEP radial/angular terms. ZBL derivatives and multi-element AlAs/GaAs interfaces are not covered by this executable.
- M2 and M3 documentation now describes nonoverlapping blocks and accumulator resets, while explicitly stating that adjacent blocks are not guaranteed statistically independent.
