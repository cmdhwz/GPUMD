# R164 diagnostic readout

This opt-in development readout records full-bead phase and forces and, optionally, provisional ordinary-path centroid observables. It does not establish production acceptance, a real P11 event, a complete checkpoint, or conductivity. The native short-run build and comparisons described below have been performed. WPE full linking and runtime, physical event accounting, production acceptance and long-time transport remain unverified.

Prepare the frozen R161 phase with the matching target model, using a fresh directory:

```
python tools/r164_phase_to_restart.py R161_phase.npz restart_beads.xyz --temperature 300 --model-output model.xyz
```

Copy `examples/r164_diagnostic/run_0p2fs.in` or `run_0p1fs.in` to `run.in` in separate fresh run directories with `model.xyz`, `restart_beads.xyz`, and the exact target model as `qnep.txt`. These cards use 0.2 fs × 5 and 0.1 fs × 10, respectively; they are short diagnostics, not production authorization. The generated restart prints mass to four decimal places in amu; the matching model retains 17 significant digits. GPUMD uses model masses, so reconstruct momentum using the model mass. The existing native bead restart writer also uses four decimals for mass only.

The command `r164_rpmd r164_output 1` creates a fresh directory, with debug frames every step. A zero debug stride keeps initial and final frames only. Use `r164_rpmd r164_output 1 observer` to create a separate native centroid qNEP/PPPM observer, or `r164_rpmd r164_output 1` for the phase-only run used in paired propagation checks. The main bead force route remains native GPUMD or WPE according to the build. The driver allows only `dump_thermo` and `dump_pimd_restart` alongside it and rejects other actions/properties or corrections, non-RPMD, unloaded beads, non-exact propagation, nonperiodic/nonorthogonal cells, and ambiguous or changed first-bead MIC branches.

Optional atomic checkpoints are enabled with `r164_rpmd r164_output 1 observer checkpoint 100` or `r164_rpmd r164_output 1 checkpoint 100`. The checkpoint stride must be positive and `observer`, if present, precedes `checkpoint`. Initial, final and stride steps have a frame and force-image file; debug and checkpoint cadences are combined without duplicate files. After those files, the geometric log and the scalar row are closed, `checkpoint_<step>.txt` is atomically committed. Its `r164_checkpoint_v1` receipt records step, fixed-step time and SHA-256 of metadata, source identity, frame, images the scalar row and the accumulated scalar prefix. Hash each scalar row after stripping its CR/LF terminator and appending one LF; this is independent of Windows text line endings. A frame without its valid receipt is not a committed checkpoint. `COMPLETE` is written after the final receipt. The checkpoint supports fresh-cache reconstruction only; physical event history is unavailable, and the offline chain workflow below checks fresh-cache segment links.


`metadata.txt` records dimensions, units, R27 source identity, cell, temperature and fixed dt. Scalar time is computed as integer step × fixed dt from a zero start; it does not change GPUMD's accumulated simulation time. `source_identity.txt` records backend, model and `run.in` SHA-256 where readable, and the initial/step force-call mapping. Machine/GPU/driver identity is not recorded by the driver. The hash records source bytes at capture, not verification of the frozen target or any future run. The observer identity separately records model hash, spacing, and per-frame mesh/call identity.

Bead phase and output buffers use FP64 with 17-digit text serialization; native qNEP includes FP32 model/intermediate arrays and PPPM uses FP32 complex FFT meshes, while the indicated reductions and phase storage use FP64. These are implementation-level types, not a measured numerical error budget or a certification of WPE runtime precision.

At each whole step `scalar.txt` contains the ring energy components, total centroid momentum and four raw species number flows. The optional observer emits five separately marked unverified candidates: convection, local, mesh mechanical, charge relay and projection. It also emits source-derived local, mechanical, relay and projection image terms; the independent regular first-moment expression, regular-minus-b residual, and both site-rate minus energy-gradient power and site-rate plus native-force power. No tolerance or pass is inferred. When all five components are available, `B_UNVERIFIED` is their sum; `J2_UNVERIFIED` additionally requires the fixed R27 candidate. The R27 ID/hash, original support rows and units are recorded, but full row identity, local environment, model binding and the quantum mapping remain unverified. Unavailable values use explicit status labels, never placeholder zeroes. A successful calculation is a pointwise diagnostic, not a scientific gate pass.

Committed `frame_<step>.txt` files contain full-bead q, p, U, F. Corresponding `force_images_<step>.txt` records integer images in `q_lift = q_force + cell*image`. `geometric_chart_changes.txt` is written only for image changes between adjacent actual force frames; it counts changed bead-coordinate indices and does not localize a crossing or contain event energy/history. It is not a P11 event record. `COMPLETE` means only that diagnostic capture reached its last step and checked its output closes. Missing COMPLETE means capture is incomplete.

Convert a committed frame to a portable archive with `python tools/r164_frame_to_npz.py r164_output STEP frame.npz`; this checks the unique scalar row, final newline, step and fixed-dt time. The archive can be supplied to the accompanying `verify_ja_frame.py`. Compare observer-off and observer-on runs on the same initial phase, backend, model, PPPM, step and frame. The native comparison below quantifies their differences; it does not establish bitwise identity, prove cache isolation, or attribute those differences to a specific cause.

For fresh-cache diagnostic reinitialization from a committed frame:

```
python tools/r164_phase_relaunch.py r164_output STEP fresh_segment
```

The command preserves q/p, rejects lifts outside the force wrapper's one-cell range, creates a new NPZ and matching model/restart pair, and commits a parent receipt last. The receipt hashes the selected scalar row, the parent files at receipt creation and the new files. The scalar file can subsequently grow; the recorded parent identity does not verify a future execution. New run step 0 is the parent frame and must be deduplicated in comparisons. Caches are rebuilt, while time continuity, neighbor/event history and RNG state are not restored. Neither this workflow nor the existing bead restart is a complete seamless checkpoint; compare with an uninterrupted trajectory before claiming continuity.

Physical event localization, source-path energy transfer and event first moment remain unavailable. Full equilibrium sampling, long-run statistics, step/bead convergence, quantum-current mapping, and conductivity remain outside the validated scope.

Finite-time offline correlations can be computed with `python tools/r164_provisional_correlations.py r164_output --max-lag 10 --output correlation.json`. Multiple complete directories are accepted only with matching backend, model and run input hashes, R27 reference, bead/atom count, spacing, temperature, dt and cell; each must have contiguous scalar steps and a COMPLETE marker. The tool uses one mean and a common sample domain for the ordered full 18×18 tensor, its four b/d2 blocks, species cross correlations and trapezoidal integrals. Its paired covariance uses two nonoverlapping blocks per eligible trace and does not claim statistical independence. It reports finite-time regular-path candidates only, without physical events, volume/temperature normalization or conductivity.

The correlation output also contains a regular-only Einstein–Helfand finite-window comparison: it uses trapezoidal interval averages, actual contiguous origins within each trace and a common interval-bin mean. The reported Helfand covariance and triangular correlation integral have different finite-sample endpoint weights and are not asserted equal except in the one-interval identity test. There are no event increments, volume or temperature normalization, or conductivity estimate.

Optional `python tools/r164_provisional_de.py --parameters R27_固定双模参数与初态基准.json --output de.json frame0.npz frame1.npz ...` replays fixed-reference D/E from contiguous full-bead frames, verifies the parameter SHA and support/mass/cell, and reports projected bead-mean force, generator feedback, kick/drift mismatch and polynomial endpoint residuals. The C coefficients are inherited static evidence; full Hessian, model/backend equivalence and physical-event validity remain unverified. D/E is a diagnostic of supplied frames, not production acceptance.

D/E replay requires NPZ frames exported from the same R164 capture directory: the exporter binds the resolved directory and byte identities of metadata, source identity and the committed initial frame. Explicit atom-row and bead-order arrays must also match. Manually assembled archives without this provenance and frames from different captures are rejected, even if their step numbers are consecutive. This binding establishes common recorded provenance, not a guarantee that files or a physical trajectory are scientifically valid.

To repeat the short-run comparison on recorded outputs, use the two observer-enabled step sizes and a matching observer-disabled fine run:

```
python tools/r164_verify_short_runs.py --coarse coarse/r164_output --coarse-run-in coarse/run.in --fine fine_on/r164_output --fine-run-in fine_on/run.in --observer-off fine_off/r164_output --observer-off-run-in fine_off/run.in --phase GPUMD_r157_initial_phase.npz --cpu-forces R157_CPU_初态势力.npz --output short_review.json
```

The verifier accepts only the provided nine-command thermostat-free cards with per-step debug output, checks their original `run.in` hashes, source model/model.xyz/restart hashes, metadata, atom order, committed frame and force-image files, and matching source configuration. It reports all-step H/(PN), each drift from the initial value and its maximum, coarse/fine common-time and observer on/off differences. Observer candidate coverage and unavailable components are explicit; geometric image comparisons are not P11 events. CPU U/F differences are calculated only when initial q(MIC) and p both agree within 1e-8; frozen phase, CPU and potential hashes are independently identified, and nonmatching references are labeled UNVERIFIED. The verifier alone does not establish runtime/GPU or actual binary identity; no unestablished threshold is called a physical pass.

For every frame, the short-run verifier independently reconstructs U, K, ring-spring energy, H/(PN), centroid momentum and four species number flows from q, p, bead U and model masses. It rejects a frame/scalar mismatch using a fixed arithmetic-only allowance of `1e-10 + 1e-10 × sum(abs(contributions))` for each quantity and reports the signed residual, contribution sum and allowance per step. This checks synchronization and serialization arithmetic; it is not a force, trajectory or physical acceptance tolerance. Observer-off runs containing an observer identity file or candidate component are rejected.

## Recorded native short-run evidence

At source commit `e9a4876d`, the 150 compilation units in the CMake `gpumd` source set were compiled and linked directly with CUDA 12.2.140 and MSVC 19.29. This was a direct build of that source set; the local CMake generator probe remained unresolved. On an NVIDIA GeForce RTX 3060 Laptop GPU with driver 551.86, native R161 runs completed for 0.2 fs × 5 with the observer on and 0.1 fs × 10 with the observer on and off. The short-run verifier's frame/scalar arithmetic checks passed for all recorded frames. The machine-readable comparison is `short-run-verification.json` in the `native-r161-e9a4876d` evidence directory.

At the initial phase, the maximum CPU-reference position difference under MIC was 0 Å and the maximum momentum difference was 2.8422e-14 eV fs/Å. The maximum and RMS force differences were 1.24814e-4 and 1.95078e-5 eV/Å. The mean per-bead potential-energy offset was −3.15814e-4 eV, with maximum centered difference 2.82298e-4 eV. These are measured differences, not a pass against an agreed backend accuracy threshold.

The maximum full-window drift in H/(PN) was 5.3016 µeV/atom for the coarse observer-on run and 1.0060 µeV/atom for the fine observer-on run. At common times the maximum coarse/fine q difference was 5.7239e-4 Å; at 1 fs it was 5.20977e-4 Å. Across the 11 fine observer-on/off frames the maximum q, p and F differences were 2.59082e-8 Å, 6.29486e-6 eV fs/Å and 6.3993e-5 eV/Å. The first-frame F difference was 2.55927e-6 eV/Å, before the observer calculation. These comparisons neither show bitwise identity nor identify the cause of the differences.

At coarse step 3, the y separation of atom pair (346, 1539) was 5.21336e-10 Å from L/2. Projection, b and J2 were unavailable at that frame under the ambiguity guard; they were available in all 11 fine observer-on frames. The fine observer-on D/E replay and provisional correlation analysis executed; the maximum D identity residual was 1.39e-17 eV Å/fs and the E endpoint residual was 5.51e-17 eV Å. These are finite-window arithmetic diagnostics, not proof of physical event treatment or converged transport.

`run.cu` and `r164_rpmd.cu` also compiled individually with the WPE definition and distribution headers under CUDA. Full WPE Linux linking and runtime were not tested. No result above establishes a P11 event, a production threshold, equilibrium independence, bead or timestep convergence, or long-time conductivity.

Two observer-off runs with the same configuration showed maximum q, p and F differences of 2.63927e-8 Å, 6.26948e-6 eV fs/Å and 6.34715e-5 eV/Å. Their first-frame F difference was 2.89991e-6 eV/Å and their force-image difference count was zero. These values are of the same order as the observer on/off differences and establish observed run-to-run variation within this comparison, without assigning its cause. See `observer-off-repeat-comparison.json`.

A fresh-cache restart from fine-on step 5 (0.5 fs) completed five further steps. At the seam, q differed by 0 Å under MIC, p by at most 2.84217e-14 eV fs/Å and F by at most 3.79980e-6 eV/Å. Across the six common phase points, maximum q and F differences were 3.61443e-9 Å and 2.04742e-5 eV/Å, with no force-image changes. Cache and event histories were not retained, so this is a bounded fresh-cache comparison rather than complete production restart validation. See `restart-step5-comparison.json`.

The native `dump_pimd_restart` output was checked over 194,568 atom rows: all mass fields had four decimal places, with maximum difference from the model mass of 4.97291e-5 u. See `native-restart-writer/mass-check.json`.

## Native assignment-center localization

For a completed native R164 capture and its original `run.in` and `stdout.log` in the same run directory, locate one selected coordinate's existing center change with, for example:

```
python tools/r164_locate_native_crossing.py fine-on/r164_output --run-in fine-on/run.in --stdout fine-on/stdout.log --step 0 --bead 0 --atom 5609 --axis z --output crossing.npz
```

The tool checks input hashes and short-run configuration, the completed capture, both whole-step frames and force-image arrays, frame/scalar arithmetic, and the unique printed PPPM grid. It reconstructs the exact free-ring substep after the first half-kick and requires all-bead q and final p replay errors no larger than 1e-8 in their declared units. A selected-coordinate acceleration bound must certify monotonicity; the tool does not certify other coordinates. The FP32 assignment-center transition is bracketed between adjacent float32 values, with the binary64 midpoint used as the threshold. The root bracket describes floating-point bisection of the reconstructed drift, not an error bound on actual device substep time. The selected coordinate must remain in one force-image chart, and recorded and replay endpoint labels must agree. The NPZ contains a JSON receipt with file hashes, threshold, nominal-half-grid difference, root bracket, monotonic bound and two-sided samples, plus q and free-substep p for every atom of the selected bead at the left, root and right times. The stdout is matched by directory and printed facts, but is not cryptographically bound to the capture. WPE localization is rejected because its numerical mesh convention has not been established here.

For the native R161 fine-on step 0 to 1, bead 0 / atom 5609 / z changed center 59 → 58 at the actual FP32 threshold 28.57763906824748 Å and approximately 0.00036163225 fs into the drift. This is a numerical assignment-branch localization on the recorded trajectory, not a physical P11 event or inserted impulse.

Separate native static side probes at the common-root geometry changed only atom 5609's z coordinate by ±2e-9 Å. The recorded charges were identical and the rounding model showed only that assignment center changing. The per-site reciprocal-energy sums differed by +1.98184e-7 eV, while the same-side repeat differed by −6.89162e-7 eV; both corresponding total-potential differences were 0 at the reported output precision. With frozen raw charges and G, FP32 stencil values and an FP64 paired FFT contraction gave −5.53347688e-8 eV; its real-space and Fourier forms differed by 1.32e-23 eV. Exact rational quartic stencils aligned to common grid nodes at the nominal half-grid point had zero differences through derivative order 3. These checks are limited to the selected numerical branch: the recorded bead propagation did not evaluate both sides at the root, and no physical first moment, winding, or complete event coverage follows. See `native-assignment-side-probes/sides-review.json` and `native-assignment-side-probes/exact-assignment-center-trace.json`.

Separately, the official WPE `WpeGpumdStageState` host code was tested with the actual observer-on/off nine-command cards and gave the same stage P=32, N=5896, PPPM spacing 0.5 and facts=0; see `wpe-r164-host-stage/stage-check.log`. This is a host-stage check, not a WPE numerical backend run.

Fresh-cache 32-bead first-force side probes loaded q differing only at [0,5609,z], with identical p and force images. Target-bead U differences were zero in both cross-side and same-side comparisons; maximum F differences were 1.66893e-6 and 1.54972e-6 eV/Å, respectively. These reinitialized first forces were not inserted into the recorded trajectory and do not establish cache/history equivalence. See `native-assignment-bead-probes/bead-sides-review.json`.

Checkpoint segments can be prepared and verified with:

```text
python tools/r164_checkpoint_chain.py prepare parent/r164_output 4 child --steps 6
# Run GPUMD in child; then verify the actual captures:
python tools/r164_checkpoint_chain.py verify parent/r164_output child/r164_output --output chain.json
```

Preparation verifies the parent receipt and scalar prefix and writes a parent link only after creating the four child inputs. The chain requires a known clean Git build label for each segment; that label is not a binary hash. The link records intent; verification binds it to the actual child capture and compares its step-zero lift, momentum and force images to the parent endpoint. It reports force, bead energy and available current differences without a physical acceptance threshold. Intermediate captures may end at a committed checkpoint without `COMPLETE`; the final capture requires both its final checkpoint and `COMPLETE`. The merged report contains one copy of each seam row and is a diagnostic record, not transport-tool input. Cache and physical-event histories remain unavailable.

The WPE makefile records the GPUMD source commit and worktree dirty status when Git is available. These labels are not a binary-content hash or a WPE engine version. Rebuild the GPUMD objects after changing the checkout to refresh them.

An optional native serial mode-2 PPPM trace can be requested with `r164_rpmd r164_output 0 observer checkpoint 2 pppm_trace 0 0 5609`. The last three nonnegative integers select the starting complete step, bead and zero-based atom; trace output is collected at that step and the next on their existing bead-force calls. It requires one native unbatched serial qNEP PPPM potential without DFTD3; WPE trace is unavailable. Debug and checkpoint frame cadences are combined with the two trace steps. A trace receipt is committed only after the raw files, frame, images and scalar row close successfully. The pre-electro file records the raw charge and accumulated site potential before charge normalization and the electrostatic call; mesh and assignment files contain the actual evaluated PPPM data and identify the per-atom versus global reciprocal-energy branch. The integer assignment center and stencil offsets determine unwrapped mesh indices. Neighbor history and physical events remain unavailable; no additional force is evaluated. The checkpoint-chain tool rejects trace schedules because restart scheduling has not been defined.

The `r164_pppm_trace_v2` receipt also binds a `*_descriptor_neighbors.out` file to the same force evaluation. For the selected center, the large-box descriptor records each actual radial and angular slot immediately after its float MIC, together with the integer image and candidate-cache generation before and after update.
